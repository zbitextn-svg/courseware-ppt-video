## 工作循环

每页 PPT 都走这个循环，**不要一次性写完所有页再检查**：

```
1. create 新建文稿（16:9，统一主题色/字体体系）
2. upsert-dsl --dsl-file <page.dsl> --page-index <N>   # N 为 0-based
3. lint          # 结构校验
4. screenshot --page-index <N> --out <shot.jpg>   # 用视觉核验实际渲染效果
5. 有问题 → 改 DSL → 重新 upsert-dsl → 再截图
```

关键经验：
- **lint 常误报**：对 absolute 容器的 child-containment 会保守报警。以 screenshot 实际渲染为准，渲染正常就放行。
- **每页必须截图核验**，尤其溢出问题（多列卡片、长文本）lint 查不出来。
- DSL 容器内支持 JSX 风格 `.map()` 语法批量生成同类卡片，目录页/材料清单页用它最省。
- 旧 `.ppt` 格式先 `soffice --headless --convert-to pptx` 转新格式再处理。
- 只有 Word 教案时：先读教案提炼每页要点，再从零构建整套视觉（含 AI 生成插画）。

## 画风差异化（防同质化）

用户明确反馈过「同质化有点严重」。**每份课件从主题衍生专属画风**，禁止套同一模板：

| 课件主题 | 画风示例 |
|---|---|
| 火车绘本故事 | 天蓝 × 火车黄，铁轨装饰线 |
| 漱口刷牙 | 薄荷绿 × 水泡泡元素 |
| 玩具收纳 | 积木三原色，方块圆角 |
| 风车手工 | 晴空蓝 × 纸艺质感 |
| 国庆节 | 中国红 × 金黄，旗帜/灯笼元素 |
| 山楂果 | 山楂红 × 果叶绿，全插画 |
| 星空主题 | 深蓝夜空 × 星光黄 |
| 体育教研 | 橄榄绿 × 运动橙 |
| 益智区 | 蓝紫 × 拼图块造型 |
| 项目制足球 | 草皮绿 × 白色球场线 |
| 建构游戏 | 蓝图深蓝 × 原木橙，网格底纹 |

方法论：主题名词 → 提取 2 个代表色 + 1 个装饰母题（线条/形状/元素）→ 贯穿封面、目录、内容页、结尾页。

## 版式规范

- 尺寸 16:9（1280x720 逻辑像素）。
- 中文字体统一声明「微软雅黑」或「苹方」；渲染机器缺字体会出方块，见 video-pipeline.md 的 fix_fonts。
- 标题区留白足，卡片间距 ≥ 24px，避免贴边。
- 多列卡片布局控制列宽总和 + 间距 ≤ 可用宽度，溢出是最高频问题。
- 每页信息密度：幼儿课件每页 ≤ 5 个内容块；教研课件可适当加密但要有层级。

## 素材处理

- **AI 生成图片先裁水印**：豆包等生成的图统一裁掉底部 6-7%。
- **大照片先压缩再引用**：长边 1400px、JPEG q86，否则 pptx 巨大且渲染超时。
- 照片转 JPEG 后，slides DSL 里的 `.png` 引用要批量替换为 `.jpg`（用 Python `open().read().replace()`，macOS `sed -i` 处理中文路径不可靠）。
- 媒体文件扩展名以 `ls` 实际确认为准，不要信记忆。

## QA 检查

交付前逐项过：
1. 每页截图无文字溢出、无元素重叠
2. 字体在目标机器可渲染（或已随管线 fix_fonts）
3. 文件体积合理（纯文字课件 < 5MB，照片课件 < 10MB）
4. 页数、目录与实际内容一致
5. （如做视频）确认后才进入视频管线
